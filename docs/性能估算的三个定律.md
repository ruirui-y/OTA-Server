# 性能估算：三个定律和一组实测数据

日期：2026-11-11

---

## 一、Little's Law（利特尔法则）

**排队论的基础定理，1961 年 John D. C. Little 证明。**

```
L = λ × W
```

| 符号 | 含义 | 单位 |
|---|---|---|
| L | 系统中平均请求数（在途数） | 条 |
| λ | 吞吐量 | 条/秒 |
| W | 每个请求的平均驻留时间 | 秒 |

### 适用条件

- **稳态**：系统不处于启动或排空过程中
- **长期平均**：看的是平均值，不是某一瞬间

**它不对到达分布做任何假设**，这是它比 M/M/1 更普适的地方。

### 闭环下的直接推论

如果并发数是固定的 N（闭环压测，每个请求完成才发下一个），那么：

```
L ≡ N
W = N / λ
```

**这是恒等式，不是估算。**

## 二、M/M/1（单队列单服务台）

**排队论经典模型。**

```
ρ = λ / μ           利用率 = 到达率 / 服务率
W = 1 / (μ - λ)     平均驻留时间
```

当 `ρ → 1` 时，`W → ∞`，发散速度是 `1 / (1 - ρ)`。

```
ρ = 0.5  → W = 2/μ
ρ = 0.8  → W = 5/μ
ρ = 0.9  → W = 10/μ
ρ = 0.95 → W = 20/μ
ρ = 0.99 → W = 100/μ
```

### 适用条件

- **开环**：请求从外部源源不断地来，不会因为系统慢就暂停
- 到达服从泊松分布、服务时间服从指数分布

### 本项目的适用性

我们的生产流量是开环（5 万设备定时发心跳，不管服务端快慢），**M/M/1 的结论——「利用率逼近 1 时延迟发散」——直接适用**。

但压测是闭环（固定并发），下文的实测部分用 Little's Law，不用 M/M/1。

## 三、Amdahl's Law 和 Universal Scalability Law

### Amdahl's Law

```
加速比 = 1 / (s + (1 - s) / N)
```

`s` 是串行部分占比。**串行部分决定了加速比的天花板**：
`s = 5%` 时，无论加多少核，最多快 20 倍。

### Universal Scalability Law（Neil Gunther）

在 Amdahl 基础上加了「一致性开销」：

```
X(N) = N / (1 + σ(N-1) + κN(N-1))
```

| 参数 | 含义 |
|---|---|
| σ（争用） | 串行化部分，如全局锁、共享计数器 |
| κ（一致性） | 缓存同步开销，节点越多惩罚越重，是 N² 项 |

**因为多了 N² 项，吞吐会有一个峰值，之后不升反降。**

这解释了「加机器不是线性增长」——为什么加到某个数量之后 QPS 反而下降。

| 2,048 | 2,277,705 | 819 µs | 899 µs | — |
| 4,096 | 3,351,427 | 1,211 µs | 1,222 µs | 99% |

## 五、用定律解释这组数据

### 为什么 4096 → 8192 涨不动

闭环下 `W = N/λ`，所以：

```
N 翻倍 → 如果 λ 不变，W 必然翻倍
实测 W 从 1211 → 2297（+90%），说明 λ 基本没变
```

**λ 上不去，是因为它已经接近服务端能提供的服务率上限。**

Little's Law 只能说「λ 卡住了」，**它不解释为什么卡住**。
服务率由什么决定，是算力问题：`服务率 ≤ 核数 / 每请求CPU时间`。

### M/M/1 在生产环境的意义

生产是开环。按 M/M/1，如果服务率 μ 固定，到达率 λ 逼近 μ 时延迟按 `1/(1-ρ)` 发散：

```
ρ = 0.5  → 延迟是纯处理时间的 2 倍
ρ = 0.9  → 10 倍
ρ = 0.99 → 100 倍
```

**这就是为什么容量规划一般把水位控制在 60~70%，而不是 95%。**

我们现在的水位：`λ / μ ≈ 9,975 / 76,900 = 13%`（假设单线程服务率 76,900）。

## 七、算不出来的部分

公式给的是一阶近似。下面这些必须实测：

- **服务率 μ 到底是多少**——它随负载变化（批处理摊薄固定开销），不是常数
- **拐点在哪**——只能扫在途窗口，看 QPS 什么时候停止增长
- **争用和一致性开销**（USL 的 σ、κ）——要拿多组 N 的实测数据拟合

**NebulaRPC 那组扫描就是这个用途：4096 → 8192 QPS 只涨 4.4%，说明拐点在 3.3~3.5M 之间。**
